# သင်ခန်းစာ - Hysteria 2 + Amnezia Stealth စနစ် မည်သို့ အလုပ်လုပ်သနည်း

ယခု သင်ခန်းစာမှာတော့ ဒုတိယဆာဗာမှာ တပ်ဆင်ခဲ့တဲ့ **Hysteria 2 + Zin Panel + Amnezia Stealth Setup** ရဲ့ နောက်ကွယ်က အံ့မခန်း နည်းပညာတွေနဲ့ လုံခြုံရေး ဗျူဟာတွေကို လေ့လာသွားကြပါမယ်။

---

## ၁။ လမ်းကြောင်း စီးဆင်းမှုပုံစံ (Traffic Flow)

ဒီစနစ်ဟာ 3x-ui ထက် ပိုပြီး ရှုပ်ထွေးပါတယ်။ ဘာလို့လဲဆိုတော့ Nginx ရော၊ Hysteria ရော၊ Amnezia ရော အားလုံးက ဆာဗာတစ်ခုတည်းမှာ ပြိုင်တူ အလုပ်လုပ်နေလို့ပါ။

```mermaid
graph TD
    A[သင့်ဖုန်း / ကွန်ပျူတာ] -->|TCP 443 (ရိုးရိုး အင်တာနက်)| B{Nginx <br>အဝင်ပေါက်}
    A -->|UDP 443 (QUIC)| C[Hysteria 2 Core <br>VPN အင်ဂျင်]
    A -->|UDP 58210| D[Amnezia WG <br>VPN]
    
    B -->|ရိုးရိုး ဝင်ကြည့်လျှင်| E[Fake Website <br>အတုအယောင် စာမျက်နှာ]
    B -->|/admin_xxx ဖြင့် ဝင်လျှင်| F[Zin Panel <br>Node.js: 3000]
    B -->|Amnezia URL ဖြင့် ဝင်လျှင်| G[Amnezia Panel <br>Proxy: 51831]

    F -->|Data အသုံးပြုမှု မေးမြန်းခြင်း| C
```

ဒီပုံအရဆိုရင် အပြင်ကနေ ကြည့်တဲ့သူတိုင်းက **Nginx** ကိုပဲ မြင်ရမှာဖြစ်ပြီး၊ သင့်ရဲ့ VPN ဒေတာတွေကတော့ Nginx ကို ရှောင်ကွင်းပြီး Hysteria (UDP) ဆီကို တိုက်ရိုက် စီးဆင်းသွားတာကို တွေ့ရပါမယ်။

---

## ၂။ Nginx နှင့် Website အတု ဖန်တီးခြင်း (The Fake Website)

```bash
wget -r -l 1 -p -k https://www.bing.com
```
**ရှင်းလင်းချက်:**
* Hysteria 2 ရဲ့ အဓိက လုံခြုံရေး ဗျူဟာက ဆာဗာကို ရိုးရိုး Website အစစ်တစ်ခုလို အတိအကျ ဟန်ဆောင်ထားခြင်းပါ။ 
* ဒါကြောင့် `wget` Command ကို သုံးပြီး အခြား Website တစ်ခုခု (ဥပမာ- bing.com) ကို ဆာဗာထဲကို Download ဆွဲချလိုက်ပါတယ်။ 
* MPT သို့မဟုတ် ATOM ကနေ သင့်ဆာဗာကို "ဒါ ဘာဆာဗာကြီးလဲ" ဆိုပြီး Browser ကနေ လှမ်းစစ်ဆေးတဲ့အခါ VPN စနစ်ကို လုံးဝ မတွေ့ရဘဲ၊ ရိုးရိုး Website (HTML, CSS, ပုံများ) ကိုသာ တွေ့သွားမှာ ဖြစ်ပါတယ်။ ဒါကို **Active Probing Defense** လို့ ခေါ်ပါတယ်။

---

## ၃။ UDP Port 443 ၏ လျှို့ဝှက်ချက် (The QUIC Protocol)

* ရိုးရိုး Website (Nginx) တွေက **TCP Port 443** ကို သုံးပါတယ်။
* Hysteria 2 ကတော့ **UDP Port 443** ကို အသုံးပြုပါတယ်။ 
* TCP နဲ့ UDP ဟာ လမ်းကြောင်း မတူတဲ့အတွက် Port နံပါတ် (443) တူနေရင်တောင် တစ်ခုနဲ့ တစ်ခု လုံးဝ မငြိပါဘူး။ 
* ဒါကြောင့် ISP တွေက "Port 443 ဆိုတော့ ရိုးရိုး Website လမ်းကြောင်းပဲ" လို့ ထင်မှတ်သွားပြီး ဖြတ်သန်းခွင့် အပြည့်အဝ ပေးလိုက်တာ ဖြစ်ပါတယ်။

> [!TIP]
> **Port Hopping (Port များ ခုန်ပျံခြင်း)** <br>
> Hysteria 2 မှာ Port Hopping ဆိုတဲ့ စနစ် ပါပါတယ်။ ISP ကနေ သင့် Port ကို ပိတ်ဖို့ ကြိုးစားရင် Hysteria က အခြား Port တွေ (ဥပမာ 40000 ကနေ 50000 ကြား) ကို အလိုအလျောက် ပြောင်းလဲ ချိတ်ဆက်သွားနိုင်တဲ့အတွက် အပိတ်ခံရဖို့ ဆိုတာ လုံးဝ မဖြစ်နိုင်သလောက်ပါပဲ။

## ၄။ Zin Panel နှင့် လျှို့ဝှက် URL စနစ် (The Secret Door)

3x-ui Panel ဟာ သာမန်အားဖြင့် Port (ဥပမာ 2053) နဲ့ ဝင်ရတာ ဖြစ်လို့ Port Scanner တွေနဲ့ အလွယ်တကူ ရှာတွေ့နိုင်ပါတယ်။ ဒါကို ကာကွယ်ဖို့ Zin Panel မှာ-

```javascript
path_val = '/admin_' + crypto.randomBytes(3).toString('hex');
```
* **လျှို့ဝှက်တံခါး:** ဆာဗာကို အသစ်စတင်လိုက်တဲ့အခါ `admin_b598aa` ဆိုပြီး ဘယ်သူမှ ခန့်မှန်းလို့ မရနိုင်တဲ့ လျှို့ဝှက် Link တစ်ခုကို အလိုအလျောက် ဖန်တီးပေးလိုက်ပါတယ်။
* အဲဒီ Link ကို သိတဲ့သူသာလျှင် Nginx ကနေတစ်ဆင့် အတွင်းပိုင်းမှာ ပုန်းနေတဲ့ `Port 3000` (Node.js) ဆီကို ရောက်ရှိနိုင်မှာ ဖြစ်ပါတယ်။ မှားယွင်းတဲ့ Link နဲ့ ဝင်လာသူ မှန်သမျှကို Website အတုသာ ပြသထားမှာ ဖြစ်ပါတယ်။

## ၅။ Data ကန့်သတ်ချက် ဘယ်လို အလုပ်လုပ်သလဲ? (The Traffic Monitor)

Zin Panel မှာ သုံးစွဲသူတွေကို Data ဘယ်လောက်ပဲ သုံးရမယ်လို့ သတ်မှတ်လို့ ရပါတယ်။ သူက ဘယ်လို အလုပ်လုပ်သလဲ ဆိုတော့-

1. Hysteria 2 မှာ အတွင်းပိုင်း Traffic တွေကို မှတ်သားထားတဲ့ `Port 4000` (Stats API) တစ်ခု အမြဲ ပွင့်နေပါတယ်။
2. Zin Panel ရဲ့ Backend က စက္ကန့် ၃၀ တစ်ခါ အဲဒီ `Port 4000` ဆီကို သွားပြီး "ဘယ်သူက ဒေတာ ဘယ်လောက် သုံးသွားပြီလဲ" ဆိုတာကို လှမ်းမေးပါတယ်။
3. အကယ်၍ User တစ်ယောက်ဟာ သတ်မှတ်ထားတဲ့ ပမာဏ (ဥပမာ 50GB) ကို ကျော်သွားရင် Zin Panel က SQLite Database ထဲမှာ `limit_exceeded` လို့ ပြောင်းလိုက်ပြီး Hysteria ကနေ ချက်ချင်း ကန်ထုတ် (Kick) ပစ်လိုက်ပါတယ်။

## အနှစ်ချုပ်

ဒီ **Hysteria 2 + Zin Panel Setup** ဟာ အလွန် မြန်ဆန်တဲ့ QUIC Protocol ကို အသုံးပြုထားပြီး၊ Nginx နဲ့ Website အတု နောက်ကွယ်မှာ အပြည့်အဝ ပုန်းခိုနေပါတယ်။ ထို့အပြင် Amnezia WG နဲ့လည်း ပြိုင်တူ (Conflict မဖြစ်ဘဲ) အလုပ်လုပ်နိုင်တဲ့အတွက် လက်ရှိ မြန်မာနိုင်ငံရဲ့ အင်တာနက် အခြေအနေအတွက် အကောင်းဆုံးနဲ့ အမြန်ဆုံး စနစ်တစ်ခု ဖြစ်ပါတယ်ဗျာ။
